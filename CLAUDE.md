# Primitives: working notes for agents

The brief and the definition of done are private: `primitives-design/README.md` in the explorations repo (`~/explorations` on Amrith's machine). Read it before building anything if you have it; the rules below hold either way. Values come from `src/data/tokens.json`, content from `src/data/catalogue.json`; never hard-code either elsewhere. `src/styles/tokens.css` is generated (`npm run tokens`), do not edit it.

## Rules that are easy to break

- The URL is the only state. No localStorage, no cookies, no sessions (`session: false` in astro.config.mjs stays). Only exception: the consent choice.
- Instrument pages render on demand (`export const prerender = false`) so shared links arrive with their state in the HTML. Everything else is prerendered.
- Order on an instrument page is fixed: tool, explanation, related. Never text above the tool.
- Every value shown copies itself: use `src/components/tool/Copy.svelte` (or `data-copy` / `data-copy-label` on static markup). `src/lib/client/global.ts` confirms each copy with a stamp at the pointer (`src/lib/client/stamp.ts`) and announces it in the footer status slot via `say()`; nothing else floats.
- Links leave out settings at their defaults. Each instrument page has a `read(q)` and passes `defaults` (its query at empty params) to the Instrument layout; the harness strips those pairs from the header's "Copy this setup" link, sibling links and the address bar.
- Range inputs are one-way (`value` + `oninput`); binding them two-way snaps URL state to the step grid on hydration.
- Forms carry `data-form data-astro-reload` so the client router leaves them to `src/lib/client/global.ts`.
- Bundled scripts run once per session under the client router; bind with document-level delegation or `astro:page-load`.
- Copy: plain American English (color, gray), no em-dashes, never "beautiful", "premium" or "delightful". Explanations cite standards (WCAG success criteria, CSS specs).
- One theme, light. No dark mode.
- Instrument logic lives in `packages/primitives` (npm workspace), never in a Tool: pure operations, one plain object in and one out, no DOM or I/O, `InputError` on bad input, exported under the instrument's slug in its primitive's `operations`, in `packages/primitives/src/<field>/<primitive>/`. They will become `/api/<primitive>/<instrument>` endpoints and a published package; do not build those until asked. Keep UI words out of it (return `direction: 'darken'`, let the tool say "Darken").
- The Primitives mark comes only from `src/lib/logo.ts` (spec: `primitives-design/MARK.md`, private). Never type the ◰ glyph, never fill or rotate it, never set it beside the two-disc Color mark as a logo. Icons and OG images are generated by `npm run assets` into `public/` and are not committed; primitive marks in images go through `src/lib/mark-svg.ts`, which converts the catalogue's CSS geometry and throws on anything it cannot draw faithfully.
- Keep client JS under 60 kB gzipped per page; import from `culori/fn` and register only the modes you use.
- Type's font data is `src/data/fonts.json` (every Google Fonts family, with Capsize metrics), refreshed with `npm run fonts` and committed. Pages pass tools the faces a first render needs through `src/instruments/type/seed.ts`, which is server only: importing it from a Tool puts all 1,946 families in the client bundle. Tools fetch the full list lazily with `loadFonts()`. Previews load from Fontsource on jsDelivr; nothing requests Google.

## Requests and the email list

- `/requests` is a board of ideas that are not in the catalogue, ranked by votes. Roadmap seeds come from `src/data/roadmap-ideas.json` (`node scripts/seed-ideas.mjs` writes the migration and refuses anything the catalogue already has).
- Suggestions pass `src/lib/moderation` (links, markup, NSFW via `obscenity`, keyboard mashing and random strings via a letter-pair model, troll words, off-topic words held for review). Repeats count as a vote; catalogue matches answer "Already planned" or "already live" and are only logged.
- Visitors are salted hashes (`src/lib/server/visitor.ts`): one vote per visitor per idea, no cookies. Every write checks same-origin, a honeypot and a D1 rate limit.
- Schema changes go in a new file in `migrations/`; never edit an applied one.

## Dev server quirk

`astro dev` sometimes keeps serving a component's previous stylesheet after an edit (markup updates, styles lag one save behind). If styles look stale, save the file again or restart `npm run dev`; production builds are not affected. Screenshot with a second or so of settle time after the first load.

## Redirect workers

`workers/www-redirect` and `workers/design-redirect` deploy on their own: `npx wrangler deploy --config wrangler.jsonc` from the worker's folder. Without `--config`, wrangler finds the site build's `.wrangler/deploy/config.json` further up and refuses to choose.

## Check before committing

`npm test && npm run check && npm run build`, then look at the page at 1280×800 and 390×844: the tool must be visible above the fold.

## Fields

- Primitives publishes one catalogue per field, design first; all fields share the harness and principles and differ in catalogue, marks and tints. The direction (not scope) is `primitives-design/FIELDS.md` in the private explorations repo: read it before any field work.
- The apex serves the only field until a second one ships. Do not move the design site to `design.primitiv.es` before then; `workers/design-redirect` sends that host to the apex with a temporary 307, so the direction can flip later without a cached loop.
- `catalogue.json` names its field (`"field": "design"`); operations live in `packages/primitives/src/<field>/<primitive>/` and import from `@duskresearch/primitives/<field>/<primitive>`.
- Field output is namespaced so fields can later share one app: OG images at `/og/<field>/`, `/sitemap.xml` as an index of `/sitemap-<field>.xml`, the field in `llms.txt` and the manifest. Hosts map to fields in `src/lib/fields.ts`, and `src/middleware.ts` sets `locals.field`.
- The site title stays "Primitives". The field appears as a header label, and the landing H1 as "…of <field>.", only once there are two fields.
